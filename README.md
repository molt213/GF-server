# GF-server

《少女前线》（国服）3.0600_506 自建服务端的资源与工具。

| 内容 | 位置 |
|---|---|
| 游戏资源 —— 11.03 GiB | Release [`res-v1`](#res-v1) |
| 两个 APK —— 客户端 + 服务端 | Release [`apk-v1`](#apk-v1) |
| 存档导出工具 | [`save-export/`](save-export/README.md) |

---

## 使用教程

一句话：**装两个 App → 启动服务端 → 拉资源 →（可选）导入自己的存档 → 开游戏**。
第一次大约 20 分钟，绝大部分时间在等 11 GB 资源下载。

准备：

- 一台 Android 设备（Android 9+、64 位），留够 **25 GB** 空间
- 想用自己的号，再加一台 Windows 电脑

### ① 装两个 APK

1. 从 [apk-v1](#apk-v1) 下载 `gf_cn_506_local.apk`，装上 —— 这是游戏本体
2. 再下 `app-debug.apk`，装上 —— 这是服务端

装完桌面会出现两个图标：**少女前线** 和 **GF 私服**。

> 以前装过官方版的话要先卸载（签名不同，装不上）。卸载会清掉
> `Android/data/com.sunborn.girlsfrontline.cn` 里的资源缓存。

### ② 启动服务端

1. 打开 **GF 私服**
2. 点橙色的 **启动**，顶部变成「运行中 · 监听 8080 / 8443」
3. 让它在后台待着 —— 玩游戏期间不能杀掉

### ③ 拉资源（11 GB，只需做一次）

1. 点 **管理台** → 顶部切到 **资源**
2. 点 **从 GitHub 拉资源**（**长按**它可以改源地址和代理）
3. 弹窗点 **开始下载**，等它自己跑完

它会逐卷校验 SHA-256 再自动解压，进度看服务端日志。

> **国内直连 GitHub 基本下不动。** 长按按钮填个代理：模拟器填
> `http://10.0.2.2:<你电脑的代理端口>`，真机填 `http://<电脑局域网IP>:<端口>`。
>
> 也可以在电脑上按 [res-v1](#res-v1) 那节把 6 个分卷拼起来，再把解出的
> `android3060/` 整个推进
> `Android/data/com.gfserver.phone.debug/files/gfserver/data/cdn/`。

### ④ 导出自己的官方账号（可选）

服务端自带一份示例存档，不导出也能直接玩。想用自己的号：

> **M4 服、iOS 服都能用。** 不用选服务器 —— 工具抓完包会自己从流量里认出
> 你登的是哪个区，后续请求也跟着用它。

1. 从 [apk-v1](#apk-v1) 下载 `GFSaveExport.exe`（9.3 MB 单文件，不用装 Python）
2. **右键**它 → **以管理员身份运行**（抓包需要管理员权限）
3. 按提示打开官方 PC 客户端，登录，进到主界面
4. 顺手点开一次 **好友** 页 —— 好友列表会一起导出来
5. 回到黑窗口按回车
6. 拿到 `save-<uid>-<日期>.gfsave.zip`（就在 exe 旁边，同目录）

> **不用放进游戏目录。** 桌面、下载文件夹都行 —— 它只抓本机网络流量，不读游戏文件。
> 唯一要求：和官方 PC 客户端跑在**同一台电脑**上。需要 Windows 10 1809+（`pktmon` 是系统自带）。

细节见 [save-export/README.md](save-export/README.md)。

### ⑤ 把存档导进手机

1. 用数据线 / 微信 / QQ 把那个 `.gfsave.zip` 传到手机
2. 打开 **GF 私服** → 点 **导入存档** → 选中它
3. 出现「已接收存档 … 已排队」就成了

### ⑥ 开游戏

点 **少女前线**，等进主界面。

进不去照着查：

| 现象 | 多半是 |
|---|---|
| 「获取服务器列表失败」 | 服务端没启动，或被系统清理掉了 |
| 一直卡在加载条 | 资源没下完，或者解压还没结束 |
| 进去了但只有 1 级 | 存档没导入，用的是示例档 |
| 点按钮没反应 | 同第一条，回 GF 私服 重新点启动 |
| 拉资源报 `198.18.x.x` | 代理的 fake-ip 被旧版拦了，见[拉取资源失败](#拉取资源失败) |

## 常见问题

卡住先看这里。每条都写清「你会看到什么」和「怎么办」。

### PC 端导出存档报错

**先说最重要的一条：出错了别急着关窗口。** 最后一行 `[抓包已保留] ...` 会给一个
`.pcapng` 文件的路径。那个文件能离线复现整个流程，发出来就不用你重新登录一次。

| 你看到的 | 多半是 | 怎么办 |
|---|---|---|
| 双击没反应 / 窗口闪一下就没了 | UAC 弹框点了「否」，或根本没弹 | 右键 exe → **以管理员身份运行** |
| `找不到 pktmon.exe` | 系统太老 | 需要 Windows 10 1809 以上（`pktmon` 是系统自带） |
| `一个包都没抓到` | ① 加速器 / VPN 把流量抢走了 ② 没真正登录进去 ③ 全程没有 80 端口流量 | 先关掉加速器和 VPN；确认**已经看到主界面**再按回车；重来一次 |
| 抓包文件只有几百字节，包数 0 | 同上 | 同上。这是最常见的失败，基本全是没抓到流量 |
| `抓包里没有 getUidPC 请求表单` | 抓包期间没有发生登录 | 重来：**先**开抓包 → **再**启动游戏登录 → 进主界面 → 按回车 |
| `getUidPC HTTP 400 / 500（票据可能已过期）` | 登录完到按回车之间隔太久 | 重来，进主界面后**立刻**按回车 |
| `登录响应缺 uid/sign` | 抓到的不是登录响应 | 把那个 `.pcapng` 发出来 |
| 导出成功，但好友是 0 人 | 没点好友页，自动补拉也没成功 | 不影响其他数据。想全就重来一次，进主界面后**点开一次好友** |
| 导进手机后还是 1 级 | 存档没生效 | 看 GF 私服「存档」页签有没有 `已接收存档 … 已排队`；有的话回「资源」页再点一次**启动** |

> **不用选服务器。** M4 服、iOS 服、渠道服都能用 —— 工具抓完包会自己从请求头
> 认出你登的是哪个区，后续请求也跟着用它。

### 服务端 App 拉资源很慢 / 卡住

资源一共 **11 GB、6 个分卷**，全部走 GitHub。国内直连就是这个速度，不是坏了。

**先判断是不是「正常慢」：**

| 速度 | 说明 |
|---|---|
| 6–10 MB/s | 正常（挂了代理，或者网络好） |
| 1–3 MB/s | 能用，慢慢等 |
| 几十 KB/s，或长时间一动不动 | 等于没走代理，看下面 |

**让它快起来 —— 两选一：**

**A. 手机上自己有代理**（Clash / 加速器）
1. **长按**「从 GitHub 拉资源」
2. 「代理」填 `http://127.0.0.1:7890`（Clash 默认端口，按你实际的改）
3. 确定 → 开始下载

**B. 电脑上有代理，手机和电脑连同一个 Wi-Fi**
1. 电脑上的 Clash 打开 **「允许局域网连接」（Allow LAN）**
2. 电脑上 `ipconfig` 查内网 IP，比如 `192.168.1.10`
3. 手机 App 长按「从 GitHub 拉资源」，「代理」填 `http://192.168.1.10:7890`

**中途断了不用从头来。** 分卷是断点续传的，一次最多自己重试 6 轮 ——
日志里出现 `第 3/6 轮中断` 是正常现象，别去点停。

**下载 100% 之后不动了？** 那是在解压，11 GB 要几分钟，别关。

> 报 `ValueError: 拒绝环回/私有/保留地址：github.com -> 198.18.x.x` 的话，
> 是旧版 App 撞上了代理的 fake-ip，见 [拉取资源失败](#拉取资源失败)。

## apk-v1

两个 APK 必须装在**同一台 Android 设备**上 —— 客户端只连 `127.0.0.1`。

| 文件 | 包名 | 字节数 | SHA-256 |
|---|---|---|---|
| `gf_cn_506_local.apk` | `com.sunborn.girlsfrontline.cn` | 318,403,335 | `c973de25ecd40a7b46b73784c3d9d04db84ecc982676985dc3ce04a1344ecfd5` |
| `app-debug.apk` | `com.gfserver.phone.debug` | 189,263,984 | `1324bcdf07b9d9f31705108e378439243a214938fea65a09180441b354590a49` |
| `GFSaveExport.exe` | —（Windows 工具，非 APK） | 9,726,479 | `a2da69ee0c89defdebcb0b254972b10ea793b8d0ebefd14d40b7c905caf38fe9` |

`GFSaveExport.exe` 就是「GF存档导出」—— 在电脑上导出官方账号存档用，见[使用教程第 ④ 步](#使用教程)。不用装 Python。

### 客户端 APK

官方 3.0600_506 客户端，**用本地密钥重新签名**。相对官方包只有两处不同：

1. `res/xml/network_security_config.xml` 额外信任 APK 内置的那张 CA（以资源引用方式指向），所以**设备上不需要安装任何证书**。
2. IL2CPP metadata 里的服务器地址全部改写成 `127.0.0.1`。端口写在 URL 里（`:8080` / `:8443`），因为 Android 不允许非 root 应用绑定 1024 以下的端口。替换是等长的，溢出部分补成 `/moltxxxxxx/` 路径前缀，由服务端剥掉。

游戏逻辑、资源、反作弊库（`libtersafe2.so` / `libtprt.so`）逐字节未改。

重签名意味着签名与官方包不同，所以覆盖安装官方包必须先卸载（卸载会带走 `Android/data/<pkg>`，也就是数 GB 的资源缓存）。

### 服务端 APK

Chaquopy CPython 3.11。只监听 `127.0.0.1:8080`（HTTP）和 `127.0.0.1:8443`（TLS），不绑定其他地址。首次启动时把 `assets/server.zip` 解压到应用外部私有目录（`Android/data/com.gfserver.phone.debug/files/gfserver/`）。

内置的玩家数据是**示例存档** —— `uid 1000001`，名字 `指挥官`。要换成自己的号，在服务端 App 里点「导入存档」，选 `save-<uid>-<yyyymmdd>.gfsave.zip`。

> 服务端**没有「新号初始化」逻辑**：`content/player/l1.json` 必须存在，否则 `Index/index` 回 `error:0`，客户端过不了标题画面。这就是要在 APK 里带一份示例档的原因。

APK 里同时带着 `127.0.0.1:8443` 用的自签 CA（证书 + 私钥）。它是一个一次性的、只在回环地址上用的锚点，供上面那个客户端 APK 信任 —— **不要拿去用在别的地方**。

### 安装

```sh
adb install gf_cn_506_local.apk
adb install app-debug.apk
```

然后打开 **GF 私服** → 点「启动」，再开游戏。

> **覆盖安装已有环境时注意。** `server.zip` 只解压一次，靠写在 `gfserver.py` 旁边的 `.unzip-ok` 标记把关。覆盖安装会保留这个标记，所以已解压的树 —— 包括你的存档 —— 不会被动。标记缺失时（全新安装、清了应用数据、手动删过）整棵树会重新解压，`content/player/l1.json` 会被示例档覆盖。介意的话先把 `Android/data/com.gfserver.phone.debug/files/gfserver/content/player/` 备份出来。

### 资源

APK 里**不含**那 11 GB 资源树。两种拿法：

- 服务端 App 的资源页可以直接从 GitHub 拉 `res-v1` 的分卷并自动解压；
- 或者手动把 `android3060/` 目录推进
  `Android/data/com.gfserver.phone.debug/files/gfserver/data/cdn/android3060/`。

## save-export

Windows 工具，把 PC 继承版账号的当前进度导出成服务端 App 能导入的
`save-<uid>-<yyyymmdd>.gfsave.zip`。用系统自带的 `pktmon` 抓登录流量，读

## res-v1

`android3060` 全量资源 —— **11.03 GiB**，切成 6 个 tar 分卷：

```
res-android3060-part-aa .. res-android3060-part-af
SHA256SUMS.txt
```

每卷都在 1.9 GB 以内（GitHub 单个 release 资产上限 2 GB）。

### 怎么拼回去

按 `aa` .. `af` 的**顺序**拼接，得到的是一个完整的 tar 流：

```sh
cat res-android3060-part-a{a,b,c,d,e,f} | tar -xf -
```

归档里的成员路径**不带目录前缀**，所以要解到 `android3060/` 目录里：

```sh
mkdir -p android3060
tar -xf - -C android3060
```

### 校验

```sh
sha256sum -c SHA256SUMS.txt
```

每行格式是 `<sha256> *<分卷名>`。

### 服务端怎么用它

服务端 App 的资源页（「从 GitHub 拉取」）会把分卷下到 `<目标>.dl/` 缓存里，逐卷校验 SHA-256，再拼成一个只读流，把 tar 直接解到：

```
Android/data/com.gfserver.phone.debug/files/gfserver/data/cdn/android3060/
```

解压成功后分卷会被删掉。

### 拉取资源失败

**报 `ValueError: 拒绝环回/私有/保留地址：github.com -> 198.18.x.x`**

`198.18.0.0/15` 是代理软件 TUN 模式的 **fake-ip 池**（Clash 默认 `198.18.0.1/16`、
Surge 用整个 `/15`），不是真的服务器地址。开着这类代理时 GitHub 的 DNS 会被应答成
假地址，真实连接由 VPN 层按 SNI 还原；而 2026-11-13 之前的 App 会把它当内网请求拦掉。

两条路，任选一条：

- **升级 `app-debug.apk`**（上表那一版之后）—— 已能识别 fake-ip 段并放行，
  IP 字面量和真正的内网地址仍然照旧拒
- **继续用旧版**：在代理里把 GitHub 域名排除出 fake-ip

```yaml
dns:
  fake-ip-filter:
    - '+.github.com'
    - '+.githubusercontent.com'
```

mihomo / Clash Meta 改完重载配置；或者把 DNS 模式从 `fake-ip` 换成 `redir-host`。
